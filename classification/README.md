# classification/ — пайплайн классификации растительности

Многоклассовая классификация растительного покрова по многослойному композиту `Composite_filtered.tif`, подготовленному в `common/00_Prepare_Layers.py`.

## Обзор пайплайна

```
common/00_Prepare_Layers.py   →   Composite_filtered.tif + predictor_names.pkl
                                          │
                                          ▼
      01_prepare_data.py         обучающая выборка из полигонов (samples.gpkg)
                                          │
                                          ▼
      02_classification.py       отбор предикторов, диагностика, разбиения
                                          │
                                          ▼
      03_tune_models.py          обучение и оценка RF / CatBoost / LightGBM /
                                 XGBoost / Ridge / LDA / QDA (Spatial Block CV)
                                          │
                                          ▼
      04_predict_map.py          финальная растровая карта + QGIS-проект + QML
                                          │
                                          ▼
      05_classwise_importance.py per-class permutation importance + GAM-отклики
                                          │
                                          ▼
      07_generalization.py       генерализация: sieve + сглаженный вектор
                                          │
                                          ▼
      08_Topology.py             замена классов по целевым слоям (OSM) + топология
                                          │
                                          ▼
      09_MatrixLegend.py         матричная легенда (цвет × тон) → XLSX
```

## Скрипты

### 01_prepare_data.py
Собирает обучающую выборку. Читает полигоны + `Composite_filtered.tif`. Извлекает значения предикторов для каждого пикселя внутри полигона; для точечных эталонов использует `rasterio.sample()`. Сохраняет `samples.gpkg` со слоем `sample_pixels` и служебными полями `polygon_id`, `n_pixels`, `class_name`. Регистронезависимые коллизии имён слоёв (SQLite) устраняются суффиксами `_2`, `_3`; исходные имена сохраняются в `raw_layer_names`/`band_name_map`.

### 02_classification.py
Отбор предикторов и диагностика перед обучением: корреляционный анализ, тест Краскела–Уоллиса по классам, отсечение малоинформативных слоёв, диагностические графики (с автоматическим понижением DPI при риске превышения предела Agg в 65 535 пикселей).

### 03_tune_models.py
Обучение и оценка семи алгоритмов: Random Forest, CatBoost, LightGBM, XGBoost, Ridge, LDA, QDA. Разбиения: **StratifiedGroupKFold по `polygon_id`** (пиксели одного полигона не попадают одновременно в train и test) плюс пространственная блочная кросс-валидация на K-Means по координатам. Метрики: OA, каппа Коэна, TSS, F1-macro, AIC (где применимо). Сохраняет `final_models.pkl`.

### 04_predict_map.py
Строит финальный категориальный растр. Значения классов сохраняются **0-based** (`0..n-1`) с `nodata=-9999`; таблица классов, фильтр статистики и per-class циклы согласованы. Дополнительно выпускает переносимый `.qgs`-проект и сайдкар `.qml` с paletted/unique-values раскраской (палитра `1..24`, значение `v` → цвет `v+1`).

### 05_classwise_importance.py
Пермутационная важность **по классам** (что важно именно для класса `k`) и одномерные GAM-зависимости вероятности принадлежности к классу от значений признаков.

### 07_generalization.py
Генерализация классифицированной карты (номер 06 не используется). При запуске без аргументов (`%run 07_generalization.py` или `python 07_generalization.py`) открывается окно tkinter:

- **«Добавить файлы…»** — Проводник с мультивыбором `*_cat.tif`; стартовая папка — самый свежий запуск в `04_FINAL`;
- **Sieve** — минимальный размер группы (по умолчанию 5 пикс.) и соседство 4/8; мелкие группы присоединяются к преобладающему соседнему классу (векторизованный numpy, без цикла по компонентам);
- **Векторизация** — marching squares тайлами (по умолчанию 256 px, запас 16 px): сглаживание Чайкина, упрощение Douglas-Peucker, разбиение без зазоров (`repair`), сборка `patch` / `class` / `raw`, число процессов;
- **Результаты** — папка вывода и флажок «Сохранить также очищенный растр».

По умолчанию сохраняется **только вектор** `07_GENERALIZATION/<ддммгг_ччмм>_vXXX/<base>_sieveN_cM_smK.gpkg` (слой `classes`: `class_value`, `class_name`, `area`) и `run_info.txt`. Очищенный растр нужен тайловой векторизации как промежуточный файл и удаляется после неё, если флажок не отмечен; промежуточные Parquet-тайлы тоже удаляются. Названия классов берутся из `*_stats.csv` рядом с растром (разделитель определяется автоматически).

В JupyterLab по умолчанию 1 процесс: `multiprocessing` (spawn) там работает ненадёжно, многопоточный прогон лучше запускать из cmd/Anaconda Prompt. Без дисплея скрипт переходит в консольный режим; CLI сохранён (`--min-size`, `--connectivity`, `--out-raster`, `--out-vector`, `--smooth`, `--tile`, `--workers`, `--output-mode`, `--resume` и др.).

### 08_Topology.py
Топологическая коррекция полигонов классов (слой П, обычно GPKG из 07) по целевым слоям ЦС (например, OSM). Окно tkinter:

- **Слой П** — файл, слой, поле класса (числовое или текстовое), классы для замены (мультивыбор);
- **Слои ЦС** — для каждого класса один или несколько слоёв (файл, слой, необязательный фильтр `поле = значения`); порядок строк = приоритет; можно указать класс, которого нет в П;
- **Параметры** — допуск топологии, м; флажки «удалять объекты классов, не пересекающиеся с ЦС» и «записать слой topology_issues»; выходной GPKG.

Алгоритм: объекты выбранного класса в П, пересекающиеся с ЦС, удаляются; объекты ЦС (в пределах охвата П) вставляются, другие классы обрезаются по их границе; образовавшиеся пустоты делятся между соседними классами П по ближайшему соседу (диаграмма Вороного по общим границам). Новые объекты получают значение класса и его постоянные атрибуты из П (например, `class_name`), поле `topo_src` (`P` / `TS:<слой>`), пересчитанную `area`. Затем до трёх итераций проверки: снятие перекрытий, заполнение дыр, присоединение узких полигонов (уже допуска). Географическая СК обрабатывается в UTM, результат — в исходной СК.

Выход: `08_TOPOLOGY/<ддммгг_ччмм>_vXXX/<имя П>_topo.gpkg` + `run_info.txt`. CLI:

```
python 08_Topology.py P.gpkg --layer classes --field class_value \
    --target "300|osm.gpkg|water|natural=water" --target "400|bog.shp" --tol 1
```

### 09_MatrixLegend.py
Матричная легенда для полигонального слоя, класс которого задан двумя векторами (например, формация × стадия). Окно tkinter:

- **Слой** и **векторы**: два поля (по горизонтали — столбцы, по вертикали — строки) или одно поле с кодом и способом разбора: «первые k цифр | остальные» (`3125` при k = 1 → `3 | 125`), «остальные | последние k цифр» (`12125` при k = 3 → `12 | 125`), «разделитель» (`3_125`); выбирается ось первой части; показывается пример разбора;
- **названия**: CSV «номер; название» для каждой оси (разделитель и кодировка UTF-8 / Windows-1251 определяются автоматически);
- **цвет и тон**: одна ось — цвет (по умолчанию ось с бо́льшим числом категорий), другая — тон. Базовые цвета — автопалитра или вручную; способы тона: к бледному, к тёмному, к серому, от бледного через базовый к тёмному, светлота HLS, случайная в пределах цвета; сила и обратный порядок. Для каждой категории можно задать свой градиент, любую ячейку — перекрасить вручную (палитра или HEX);
- **матрица на экране**: закреплённые заголовки, перетаскивание и стрелки — сдвиг, колесо — масштаб к курсору, Shift + колесо — сдвиг по горизонтали, Home — вписать; ПКМ — меню ячейки.

Выход: `09_MATRIX_LEGEND/<ддммгг_ччмм>_vXXX/<слой>_legend.xlsx` — листы «Матрица» (ячейки залиты цветом, значение — HEX), «Классы» (код, значения, названия, HEX, RGB, число объектов), «Цвета», «Параметры» (по ним раскраску можно загрузить обратно). CLI с раскраской по умолчанию: `python 09_MatrixLegend.py map.gpkg --field code --parse first:1 --names-v veg.csv --names-h stage.csv`.

## Служебные поля (не предикторы)

Из выборки на всех этапах исключаются:

```
polygon_id  n_pixels  class_name  ID  x  y
```
