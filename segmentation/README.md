# segmentation/: фрагменты подложек вокруг точек и сегментация в samgeo

Вокруг точек скачиваются фрагменты спутниковой подложки высокого разрешения (круг радиусом 500 м вокруг каждой точки). Близкие точки попадают в один общий фрагмент, который охватывает круги всех точек группы (сторона до 2 км). Затем фрагменты сегментируются в [samgeo](https://samgeo.gishub.org/): либо выделяется сегмент каждой точки (12, подсказка-точка и спектральный фильтр, как в `sam_segment_v12.py`), либо все объекты фрагмента (11). Один огромный GeoTIFF на всю территорию не нужен: хранятся только фрагменты вокруг точек.

| Скрипт | Назначение |
|---|---|
| `10_download_sat_chips.py` | Фрагменты Google / Bing / Yandex / ESRI вокруг точек (CSV / XLSX / GPKG / SHP / GeoJSON / KML). Результат: GeoTIFF с JPEG-сжатием или JPG/PNG/WebP с файлом привязки. Кэш тайлов в SQLite, отсев ошибочных координат (`VALID_BBOX`), общие фрагменты для близких точек (`GROUP_MODE`, `GROUP_LINK_M`, `MAX_CHIP_M`), необязательный фильтр по AOI (ассет GEE или локальный файл). Таблицы `chips_index.gpkg` (охваты фрагментов) и `chips_points.gpkg` (точки с номером фрагмента и исходными атрибутами) |
| `11_samgeo_segment_chips.py` | Сегментация всех фрагментов: определение видеокарты (PyTorch и `nvidia-smi`), параллельные процессы на CPU или GPU с перезапуском после сбоя, усиление контраста, больше кадров SAM для крупных общих фрагментов (`ADAPTIVE_CROPS`), обрезка по кругам вокруг точек, связь сегментов с точками, перевод в UTM 37N. Результат: один слой `segments.gpkg` |
| `12_samgeo_point_segments.py` | Сегмент каждой точки (алгоритм `sam_segment_v12.py`): SAM 2 с точкой как подсказкой, 3 маски, отбор по доле «хороших» пикселей (расстояние Махаланобиса до эталона вокруг точки, порог χ²) внутри радиуса поиска. Перекрытия соседних точек делятся (`voronoi`) или отдаются ближайшей к центру перекрытия (`centroid`, как в v12). Атрибуты точек переносятся в полигоны. Результат: `point_segments.gpkg` со слоями `segments` (полигон на точку) и `rejected` (точки без сегмента с причиной) |

## Порядок работы

1. `pip install segment-geospatial sam2 requests pillow psutil` и PyTorch под вашу CUDA ([pytorch.org](https://pytorch.org/get-started/locally/)).
2. **Тестовый запуск**: в обоих скриптах по умолчанию `TEST_N = 20`.
   - `python segmentation/10_download_sat_chips.py`: выбрать файлы точек в окне Проводника. Скрипт скачает 20 мест и даст прогноз объёма и времени загрузки для всех.
   - `python segmentation/12_samgeo_point_segments.py` (сегменты точек) или `python segmentation/11_samgeo_segment_chips.py` (все объекты фрагментов): выбрать папку `sat_chips_<provider>_z<zoom>`. 12 обработает случайные фрагменты, в сумме около 20 точек, 11 — 20 фрагментов; оба дают прогноз времени для всех.
   - Логи и таблица времени по фрагментам сохраняются в `<папка фрагментов>/_logs/`.
3. **Полный запуск**: `TEST_N = 0`. Уже готовые фрагменты и сегменты не пересоздаются, прерванный запуск продолжается с места остановки.

## Основные параметры

- **10**: `PROVIDER` (`google` / `bing` / `yandex` / `esri`), `ZOOM` (17 ≈ 0,67 м; 18 ≈ 0,34 м; 19 ≈ 0,17 м на 55° с. ш.), `RADIUS_M`, `OUT_FORMAT`, `VALID_BBOX`, `SHEET_NAME`, `AOI_SOURCE` (`"gee"` использует ассет `GEE_AOI_ASSET`).
  - `GROUP_MODE = "merge"`: точки ближе `GROUP_LINK_M` (500 м) друг к другу попадают в общий фрагмент. Он охватывает круги `RADIUS_M` всех точек группы, длинная сторона не больше `MAX_CHIP_M` (2000 м). Крупные скопления делятся на части с минимальной суммарной площадью. Имя общего фрагмента — ID первой точки и число точек, например `108_7p.tif`.
  - `GROUP_MODE = "dedup"`: отдельный фрагмент 2R × 2R на каждое место, объединяются только точки ближе `DEDUP_M`.
  - Готовый фрагмент не перекачивается, пока не изменились состав его точек и охват (поле `key`).
- **11**: `MODEL`, `SAM2_MODEL_ID`, `PRESET` (`quality` / `fast`), `N_WORKERS`, `THREADS_PER_WORKER`, `WORKERS_PER_GPU`, `MEM_PER_WORKER_GB`, `AMG_KWARGS`, `ENHANCE`, `MIN_REGION_PX`, `ADAPTIVE_CROPS`, `CROP_MAX_PX`, `CLIP_TO_CIRCLE`, `OUT_EPSG`.
  - `ADAPTIVE_CROPS = True`: крупный фрагмент делится на сетку кадров SAM не больше `CROP_MAX_PX` (2000 пикс.), поэтому детальность такая же, как у одиночного фрагмента 1 км. Время растёт примерно пропорционально площади; прогноз считается по числу кадров.
  - Маски хранятся в RLE, мелкие островки и дырки убираются на растре меток (`MIN_REGION_PX`), поэтому память почти не зависит от размера фрагмента.
  - `N_WORKERS = "auto"` на CPU: число физических ядер / `THREADS_PER_WORKER`, но не больше, чем позволяет свободная память.
  - `N_WORKERS = "auto"` на GPU: `WORKERS_PER_GPU` процессов на карту (по умолчанию 2).
  - Веса модели скачиваются один раз в главном процессе, рабочие процессы читают кэш Hugging Face без сети (`HF_HUB_OFFLINE=1`). Если процесс не смог загрузить модель, он запускается повторно; при второй неудаче работа продолжается без него.
  - На GPU скрипт раз в 10 с опрашивает `nvidia-smi` и в конце выводит среднюю загрузку и память каждой карты; если карты загружены меньше 70% и памяти хватает, он предлагает увеличить `WORKERS_PER_GPU`.
  - Остановка в Jupyter (Interrupt) завершает и рабочие процессы; повторный запуск продолжает с места остановки.
  - Для видеокарты нужен PyTorch с CUDA. Если стоит CPU-сборка, а `nvidia-smi` видит карту, скрипт выводит команду переустановки.

- **12**: после выбора папки открывается окно со всеми настройками сегментов, модели и запуска, с пояснениями (`ASK_SETTINGS = True`).
  - Внизу окна сразу видны площадь круга поиска, минимальный объект, порог хи-квадрат и число точек, уже готовых с такими параметрами (они не пересчитываются).
  - Кнопки: «Как в v12» (без очистки, перекрытия `centroid`), «Из шапки скрипта», «Запустить» (Enter), «Отмена» (Esc).
  - Введённые значения сохраняются в `<папка фрагментов>/_points/settings12.json` и подставляются при следующем запуске. Без графического окружения те же вопросы задаются в консоли (Enter — оставить значение).
  - В окне: `SAM2_MODEL_ID`, `DEVICE`, `N_WORKERS`, `THREADS_PER_WORKER`, `WORKERS_PER_GPU`, `TEST_N`, `OUT_NAME`, `OUT_EPSG` и параметры сегмента:
  - `MAX_RADIUS_M` (150 м) — радиус поиска: наибольший радиус объекта от точки. Кадр SAM — квадрат 2R × 2R вокруг точки.
  - `CONFIDENCE` (0.95; 0.80 мягкий, 0.99 строгий) — порог χ² (3 канала) для расстояния Махаланобиса до эталона.
  - `REF_RADIUS_M` (20 м) — радиус эталонного окна вокруг точки; `REF_RADIUS_FIELD` — поле точки со своим радиусом (пустое или ≤ 0 — общий).
  - `MIN_GOOD_RATIO` (0.25) — минимальная доля хороших пикселей маски от площади круга πR². При R = 150 м это 1,77 га, меньшие объекты отклоняются.
  - `ENHANCE` — растяжка контраста для SAM (Махаланобис всегда по исходным яркостям); `MIN_SAM_SCORE` — порог оценки маски SAM (0 — как в v12).
  - `MIN_HOLE_M2`, `MIN_PART_M2` (10 м²) — заливка дырок и удаление островков сегмента; 0 — пиксельный контур как в v12.
  - `REMOVE_OVERLAPS`, `OVERLAP_MODE` (`voronoi` / `centroid`), `COINCIDENT_M` (1 м: повторные описания одного места перекрытия не делят, у каждого свой одинаковый сегмент).
  - `MIN_PART_SHARE` (0.01), `KEEP_POINT_PART`, `SIMPLIFY_M` меняются без пересчёта: достаточно запустить скрипт ещё раз. Изменение остальных параметров сегмента запускает пересчёт точек.
  - Процесс берёт фрагмент целиком: снимок читается один раз, перекрытия точек фрагмента делятся на его растре, между соседними фрагментами — по полигонам при сборке.

## Поля `point_segments.gpkg` (12)

Слой `segments`: `seg_id`, все атрибуты точки из `chips_points.gpkg` (при совпадении имён — с суффиксом `_pt`), `area_m2`, `area_raw_m2` (до деления перекрытий), `good_ratio`, `mask_idx` (1–3), `sam_score`, `ratios` (доли трёх масок), `ref_r_m`, `ref_src` (`field` / `default`), `max_r_m`, `edge` (круг поиска вышел за край фрагмента). Слой `rejected`: точки без сегмента с полями `reason`, `ratios`, `scores`, `ref_r_m`. Служебные файлы — в `<папка фрагментов>/_points/`.

## Поля `segments.gpkg` (11)

`uid`, `chip_id`, `members` (все точки фрагмента), `n_points`, `seg_id`, `area_m2`, `cut_by_circle` (сегмент обрезан границей кругов), `points_in` и `n_pts_in` (точки внутри сегмента), `near_point` и `near_dist_m` (ближайшая точка фрагмента и расстояние от контура сегмента до неё, 0 — точка внутри), `chip_key`, `geometry`.

## Примечания

- Yandex отдаёт тайлы в проекции EPSG:3395, остальные источники в EPSG:3857. Скрипт учитывает это, привязка фрагментов совпадает.
- Условия использования Google, Bing и Yandex ограничивают массовую загрузку тайлов. Для публикаций безопаснее ESRI World Imagery с атрибуцией «© Esri, Maxar, Earthstar Geographics».
- Дата съёмки у подложек неизвестна и может различаться между соседними фрагментами.
